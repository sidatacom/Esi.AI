# Session

## User Request
Die bestehende Requirement-Logik soll Backend-Anforderungen installieren können, insbesondere LLamaSharp-kompatible CUDA-12- und SYCL-16-Runtimes, damit die Solve-Aktion tatsächlich funktioniert.

## Action Plan
- [completed] Bestehende Contracts, Hub-Methoden, Client-Service und Backends-UI anhand der realen Repository-Pfade prüfen.
- [completed] Installierbares Runtime-Manifest und serverseitigen Installer im Core/Studio-Bereich implementieren.
- [completed] DTOs, IDataService, SignalRDataService und DataHub um Backend-Runtime-CRUD/Install erweitern.
- [completed] Requirement-Diagnose und Backends-UI mit der Installationsaktion verbinden.
- [completed] Tests für Manifestvalidierung, sichere Aktivierung und fehlende Assets ergänzen.
- [completed] Betroffene Projekte bauen und fokussierte Tests ausführen.

## Design Constraints
- DTOs gehören in Esi.AI.Models.
- Browser-Kommunikation läuft über IDataService, SignalRDataService und DataHub.
- Keine zusätzlichen HTTP-Endpunkte.
- Archive werden stagingweise geladen, per SHA-256 geprüft, sicher extrahiert und atomar aktiviert.
- Laufende Studio-Prozesse dürfen aktive native Dateien nicht überschreiben; nach Installation ist ein überwachteter Neustart erforderlich.

## Result

- Added `BackendRuntimeInstaller` with HTTPS-only downloads, SHA-256 verification, safe ZIP extraction, staging, and atomic activation.
- Added SignalR CRUD contracts and a local-client guard for runtime installation.
- Added CUDA 12, SYCL 16, Vulkan, and CPU route metadata with configurable package defaults.
- Added the Backends-page install action for catalog-backed LLama routes.
- Split required Intel Level Zero host validation from optional oneAPI build-tool diagnostics.
- Validation passed: Studio build and 11 focused Core tests.
- The default catalog is intentionally empty; production Solve actions require a configured HTTPS catalog or `BackendRuntime:Packages` entries with real release URLs and SHA-256 values.
