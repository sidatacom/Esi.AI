# Sitzungsprotokoll

## Benutzeranfrage

Das Layout der lokalen Modellverwaltung auf der Models-Seite und der Backend-Konfiguration soll übersichtlicher und ansprechender werden.

## Aktionsplan

- [x] Die vorhandene Modellkarten-Struktur und ihre Steuerungsgruppen prüfen.
- [x] Das Layout der Modellkarten mit klarer visueller Hierarchie verbessern.
- [x] Die Backend-Karten, Gerätezeilen und Einstellungsgruppen visuell an die Modellkarten angleichen.
- [x] Responsive Darstellung und Razor-Diagnostik prüfen.
- [x] Die laufenden Models- und Backends-Seiten validieren und das Ergebnis dokumentieren.

## Ergebnis

- Die lokalen Modellkarten verwenden ein stabiles Zwei-Spalten-Raster mit weißer Oberfläche, 4px-Radius, Rahmen und Schatten.
- Die Backends-Seite verwendet dieselbe Kartenhierarchie für Runtime-Panels, Gerätezeilen und Settings-Gruppen.
- Die Gerätezeilen stapeln sich bei 480px korrekt; die Desktopansicht wurde bei 1914px validiert.
- Razor- und CSS-Diagnostik melden keine Fehler.
- Die überwachte Studio-Session wurde kontrolliert neu gestartet, der Host war anschließend bereit.

## Nachtrag

- Ursache für das regelmäßige Aufklappen der GPU-Matrix war die dynamische `open`-Bindung an den Backend-Prüfstatus sowie der serverseitige 15-Sekunden-Requirement-Monitor.
- Die Matrix bewahrt jetzt den manuellen Auf-/Zu-Zustand über Re-Renders hinweg.
- Der Requirement-Monitor aktualisiert beim Start und danach nur noch auf explizite `RequestRefresh()`-Anforderungen statt im 15-Sekunden-Intervall.
- Browserprüfung: Matrix geschlossen, Backend-Tab gewechselt, Matrix blieb geschlossen.

## Eventarchitektur

- Ein vollständiger Seitenaufbau lädt den aktuellen Snapshot weiterhin über die jeweiligen `*_ReadAsync`-Methoden, einschließlich `LoadedModel_ReadAsync` in `Backends.razor`.
- Nach der Initialisierung werden Modellzustände ausschließlich über `LoadedModel_Create`, `LoadedModel_Update` und `LoadedModel_Delete` via SignalR aktualisiert.
- Der 250-ms-Statusvergleich während des Modellladens wurde entfernt; Load-Abschluss, Fehler und Unload publizieren explizite Lifecycle-Ereignisse.
- Der Backend-Requirement-Monitor besitzt keinen Zeitintervall-Refresh mehr und reagiert nur auf Start sowie explizite Refresh-Anforderungen.

## Backend Requirements Layout

- `BACKEND REQUIREMENTS` steht jetzt oberhalb des `SHARED MODEL CATALOG`.
- Die wiederholte Backend-`h2`-Zeile wurde entfernt; die kompakte Summary zeigt nur Label und Status.
- Die gleiche Requirements-Struktur wird für LLama, OpenVINO, vLLM, SGLang und dotLLM verwendet.
- Der eingeklappte Block wurde im Browser mit 70px Höhe validiert; die Detailansicht öffnet sich weiterhin korrekt.
