## Notes

The Reddit page and JSON endpoints were not readable in this environment: the HTML exposed only an image placeholder and the JSON endpoints returned HTTP 403.

The official dotLLM repository confirms a native .NET 10 engine with GGUF, OpenAI-compatible ASP.NET endpoints, streaming, tool calling, constrained decoding, prompt caching, paged KV-cache, speculative decoding, and CPU/CUDA backends. Its README states that continuous batching, prefix sharing, rate limiting, metrics, and tracing remain planned. The current project is GPLv3 and the latest visible release is 0.1.0-preview.3.

For Esi.AI, dotLLM is technically attractive as an embedded ASP.NET/OpenAI provider, but it is not a drop-in replacement for the current multi-vendor GPU strategy: the documented GPU path is NVIDIA CUDA, while Intel/AMD Vulkan support is not documented as available in the current dotLLM README. The GPLv3 license also requires an explicit distribution/licensing decision. The local dotLLM test additionally reproduced a Q2_K parsing limitation.

TensorSharp remains the stronger candidate for a permissive-license, cross-platform backend: BSD-3-Clause, Windows/Linux/macOS, CUDA plus Vulkan, pure-C# CPU fallback, and documented Q2-family support. Its HTTP server still uses TCP, so in-process embedding would need separate investigation.
