# Session History

## User Request
Beim Senden von Bildern kommt weiterhin der Fehler.

## Hypothesis
The parser fix was working, but OpenVINO VLM received no image tensors. The controller forwarded the `image_url` JSON into chat history while calling `VLMPipeline.GenerateWithHistory` with `null` images, which explains the native `Unknown error (-17)` after tokens had streamed.

## Findings
- The provider trace contained a valid `text`, `image_url`, `text` content array and no parser error.
- `VLMPipeline.GenerateWithHistory` requires image tensors as a separate argument; the previous adapter always passed `null`.
- Added `OpenVinoImageTensorFactory`, using ImageSharp to decode local image bytes into RGB NHWC `U8` tensors.
- OpenVINO history now receives the parsed text while the tensor array carries the image data. Tensor ownership is disposed after generation.
- Added a BMP tensor regression test covering shape and RGB pixel order.
- The rebuilt model `Qwen3.8-27B-Uncensored-int4-awq-g128-ov` loaded on `GPU.1` and recognized image input.
- A real local PNG Data URL succeeded in both non-streaming and streaming `/v1/chat/completions`; streaming ended with `[DONE]` and no trailing native error.
- Final focused tests passed 35/35 and all changed files have no diagnostics.
