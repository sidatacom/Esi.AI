# Sitzungsnotiz

## Anfrage
Die Maschine friert erneut vollständig ein. Es soll ein besserer Schutz mit einem Kernel-Watchdog installiert werden.

## Befund
- Ubuntu 26.04.1 LTS, Kernel 7.0.0-31-generic, physischer Intel-Z390-Host.
- Kein `/dev/watchdog` und keine aktive systemd-Watchdog-Konfiguration.
- `iTCO_wdt` und `softdog` sind im Kernel verfügbar; für diesen Host ist `iTCO_wdt` die bevorzugte Variante.
- `kernel.watchdog=1`, `kernel.nmi_watchdog=1`, aber `kernel.softlockup_panic=0`, `kernel.hardlockup_panic=0`, `kernel.panic=0`.
- Vorherige Bootmeldungen zeigen gleichzeitig aktive NVIDIA-, i915- und xe-Grafiktreiber.
- Installation konnte nicht automatisch erfolgen, weil `sudo -n` keine passwortlose Authentifizierung erlaubt.

## Aktionsplan
- [x] Watchdog-Hardware und Kernelmodule read-only prüfen.
- [x] systemd- und Kernel-Watchdog-Zustand prüfen.
- [x] Freeze-Hinweise aus vorherigem Boot prüfen.
- [ ] Intel-Hardware-Watchdog durch den Benutzer mit Root-Rechten laden und dauerhaft aktivieren.
- [ ] systemd Runtime- und Reboot-Watchdog konfigurieren.
- [ ] sysctl-Panic-Recovery konfigurieren und bewusst validieren.
- [ ] Nach Neustart Gerät, systemd-Werte und Bootstatus prüfen.

## Zusammenfassung
Die eigentliche Schutzschicht gehört auf Kernel/systemd-Ebene, nicht in Esi.AI. Die benötigten Befehle werden nach der Sitzung als geprüfter Root-Block ausgegeben. Die Aktivierung eines Watchdogs kann bei Fehlkonfiguration einen Neustart auslösen; deshalb wird kein riskanter Test-Hänger automatisiert erzeugt.
