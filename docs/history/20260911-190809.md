# Session

User request: Use a clean per-backend device model with `DeviceId` and `DeviceCaption` to fix incorrect SYCL device assignment.

## Plan

- [x] Replace ambiguous device fields with explicit backend device identity and caption.
- [x] Route selected Llama devices by `DeviceId` without global GPU index conversion.
- [x] Validate the affected Core and Studio projects.
- [ ] Verify the browser backend flow and record the result.

## Findings

- The UI converted selected `GPU1` into `SYCL1` even when the native SYCL catalog exposed only `SYCL0`.
- `ModelLoadStatus.Devices` is the existing backend-specific device catalog and is the appropriate source of truth.
- `DeviceStatus` now exposes `DeviceId` and `DeviceCaption`; legacy `Name` and `Description` accessors remain compatible.
- Persisted legacy `GPU*` keys are normalized against the current backend catalog, and only catalogued IDs are sent to the native loader.
- `dotnet build src/Esi.AI/Esi.AI.Studio/Esi.AI.Studio.csproj --no-restore` succeeded without warnings.
- The native request path is `LoadModelRequest.Devices` -> `LlamaLoadOptions.Devices` -> `ModelParams.Devices`.
- Legacy `GPU*` and one-based `SYCL*` aliases are migrated only when exactly one SYCL device is available; otherwise the loader rejects the ambiguous ID before native loading.
- The reported native crash was reproduced as a stale saved-device routing problem; the corrected Studio build now succeeds without warnings.
- SYCL now sets `ONEAPI_DEVICE_SELECTOR` before native backend initialization: exact `SYCL0` uses `level_zero:0`, while legacy or higher-index aliases use `level_zero:gpu` until the native catalog resolves them.
- A fresh Studio build after the selector change succeeded without warnings.

## Summary

The backend device model now separates native routing identity (`DeviceId`) from the human-readable UI caption (`DeviceCaption`). New configurations should be saved again so they persist the native backend IDs, for example `SYCL0`, instead of global GPU aliases.
