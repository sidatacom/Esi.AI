## Findings

- Studio is ready, but its current Backends page has no model selected and reports no runtime active. Its inference history contains no vLLM request; the newest entries shown are Vulkan.
- The active SQLite database has applied `20261019125200_WrapBackendConfigurationProfiles`; all saved vLLM XPU profiles are wrapped under `vllm.xpu`.
- Installed vLLM is 0.28.0. The target checkpoint declares `Qwen3_5ForConditionalGeneration`, which is present in the installed vLLM model registry.
- Prior direct load diagnostics reported engine core initialization failure. XCCL emitted `ze_driver_count 2` versus `zes_driver_count 1` and the process segfaulted. Both `libze-intel-gpu1` and `libze-intel-gpu-legacy1-1` are installed.
- The user-provided VS Code output confirms `RuntimeError: Engine core initialization failed`; repeated gRPC `Connection refused` exceptions are the bridge client observing the failed worker, not the initial cause.
- The upstream Level Zero loader source confirms `ZE_ENABLE_ALT_DRIVERS` can replace the standard driver list. The bootstrap previously removed this variable, leaving both drivers discoverable.
- A Pylance code-snippet attempt to run a native XCCL smoke test was blocked as high-risk. Do not retry that execution through another tool.
- After the process-local driver selection was deployed, the saved `Benchmark - Qwen3.8 - vLLM XPU` configuration successfully loaded `/home/llm/models/Qwen3.8-27B-GPTQ-Int4-sym-G128-MTP-BF16` on the Intel Arc Pro B70. Studio reports `Model loaded` and `1 active`; vLLM resolved `Qwen3_5ForConditionalGeneration`, initialized its engine, and created a 223,593-token KV cache. The load output includes an optional `deep_gemm` import warning for missing `libtorch_cuda.so`, but initialization completed.

## Implementation

- Updated the Core and optional XPU Python bootstraps to use `ctypes.util.find_library("ze_intel_gpu")` and, when found, set `ZE_ENABLE_ALT_DRIVERS` to that single driver for the vLLM child process.
- The environment builder is passed to `os.execve`, so this remains process-local and does not alter system packages or global settings.
