# Backend runtime repair

## User request

"dann behebe alle probleme so das alles funktioniert. Beginne mit OpenVino"

## Context

Prior backend tests found a Vulkan chat that remained in generation without an answer, a CUDA 12 model load that timed out, and a SYCL model-load attempt after which Studio became unreachable. vLLM prerequisites were missing. OpenVINO had a prior native crash with the Qwen IR model and had not yet been retested after its package pins were updated. The requested repair scope is all backend issues, starting with OpenVINO.

## Aktionsplan

1. [ ] **OpenVINO-Ursache eingrenzen**
	- [ ] Bestehende OpenVINO-Änderungen, Laufzeitdiagnosen und vorherige SIGSEGV-Belege im Repository/Protokoll lesen.
	- [ ] Studio- und Buildzustand prüfen; Host-/Kernel-/Prozesszustand sowie OpenVINO-Modellzuordnung erfassen, ohne einen Lauf zu starten.
	- [ ] Den konkreten crashenden Load-/Inference-Codepfad und den kleinsten reproduzierbaren Test bestimmen.
	- Abhängigkeit: Diagnose und Runtime-/Studio-Anweisungen lesen, bevor OpenVINO gestartet oder geändert wird.

2. [ ] **OpenVINO-Runtime ursächlich reparieren**
	- [ ] Den zuständigen Codepfad so ändern, dass der reproduzierte Fehler verhindert wird; keinen stillen Fallback auf ein anderes Backend einführen.
	- [ ] Nahe Regressionstests für den fehlerhaften Zustand und angrenzende Zustandsübergänge ergänzen.
	- Abhängigkeit: Ursache aus Punkt 1 bestätigt; Studio-Buildschranke vor jedem Build/Test einhalten.

3. [ ] **OpenVINO Ende-zu-Ende validieren**
	- [ ] Studio kontrolliert starten, Readiness prüfen und genau ein Referenzmodell über die OpenVINO-UI laden.
	- [ ] Einen neuen kurzen Chat senden; Antwort und Host-/RAM-/GPU-Zustand erfassen.
	- [ ] Bei Prozessabbruch, nativer Exception oder Freeze keine weitere Runtime starten; Ergebnis und Cleanup protokollieren.
	- Abhängigkeit: Code-/Regressionstests bestanden und sicherer OpenVINO-Start bestätigt.

4. [ ] **Übrige UI-Backends beheben und prüfen**
	- [ ] Vulkan-Chat-Hänger und CUDA-Load-Timeout anhand ihrer konkreten Logs/UI-Zustände diagnostizieren und beheben.
	- [ ] SYCL-Prozessabbruch gezielt analysieren; erst nach belegter Stabilität einen neuen Load-/Chatversuch freigeben.
	- [ ] vLLM CUDA/XPU-Abhängigkeiten prüfen und innerhalb der Nutzerfreigabe reparieren; danach Modell- und Chatpfad testen.
	- Abhängigkeit: OpenVINO ist stabil validiert; Modelle stets einzeln laden/entladen und nach jedem Lauf Hostzustand prüfen.

5. [ ] **Gesamtergebnis konsolidieren**
	- [ ] Alle verfügbaren UI-Runtimes mit demselben Referenzmodell und Chat-Prompt in einer Ergebnismatrix nachweisen.
	- [ ] Nicht verfügbare oder weiterhin blockierte Backends samt konkretem Grund nennen und Testprotokoll aktualisieren.
	- Abhängigkeit: Alle sicheren Backendläufe aus Punkt 4 abgeschlossen.

## OpenVINO-Update (2026-10-02)

- Zero-temperature OpenVINO requests now use greedy generation (`DoSample` is false); the focused backend regression test passed on Qwen2.5-1.5B-Instruct-int4-ov, GPU.
- A real Studio `/chats` request using the German UI prompt returned `OPENVINO_OK` with generation statistics. The apparent hang occurred while the debugger was paused on exceptions; after continuing, flow routing and the OpenVINO stream completed. Temporary breakpoints were removed and Studio readiness was confirmed.
- During the pause, a `SchemeNotFoundException` for `EsiFlow_2F95CC6DB33CA71BF567` was observed. It did not prevent this request from completing, but its broader significance is not established.
- The 0.5B Qwen IR model still fails in native generation with `Unknown error (-17)` on CPU and GPU, with and without streaming. This remains an OpenVINO blocker; the 1.5B UI success does not resolve it.
- Vulkan, CUDA, SYCL, and vLLM work has not yet resumed.
