## User request

Continue investigating the intermittent OpenVINO `OVException (-17)` seen in Esi.AI Studio after idle time. The user authorized rebooting into installed kernel `7.0.0-34-generic` to test whether it avoids Xe GPU faults.

- [done] Reboot and verify the running kernel, Xe GPU, and Intel user-space runtime versions.

- [done] Run the 180-second streamed two-turn request and repeat at 60 and 180 seconds.

## Summary

The user-space Intel Compute Runtime update alone did not prevent Xe GPU reset under kernel `7.0.0-38-generic`. With the same OpenVINO and Intel user-space versions, a clean Studio/model load on kernel `7.0.0-34-generic` passed 60- and 180-second streamed two-turn idle tests twice (plus one additional 180-second test) with no Xe fault/reset logs. This makes the newer `7.0.0-38` Xe kernel driver the leading cause and `7.0.0-34` a tested temporary workaround. The exact `OVException (-17)` was not reproduced, and the actual VS Code Chat UI was not driven; validation used the Studio OpenAI-compatible streaming API. Studio is left running with the model loaded for manual follow-up. Kernel `7.0.0-34` was selected for this boot only; the persistent GRUB default was not changed.
