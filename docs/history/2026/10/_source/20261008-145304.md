## Findings
- The EsiMCP extension activates inside the VS Code Extension Host and starts a workspace-local Streamable HTTP MCP server.
- VS Code's public `vscode.lm.registerMcpServerDefinitionProvider` API publishes the server URL to VS Code; default port 0 selects an assigned port, and the server binds only to loopback addresses.
- MCP `tools/list` exposes terminal, debug, and Access tools. `tools/call` dispatches to extension-owned managers; terminal/debug work therefore operates through VS Code APIs, while Access calls are forwarded to its MCP client.
- Copilot-facing `mcp_esimcp_*` names are bridge aliases/wrappers, not the MCP protocol tool IDs themselves.
- Evidence: `src/vscode/vscode-esi-mcp/src/extension.ts`, `src/vscode/vscode-esi-mcp/src/mcp-http-server.ts`, `src/vscode/vscode-esi-mcp/src/mcp/server.ts`, `.github/copilot-instructions.md`.

## Summary
Explained that EsiMCP runs as a VS Code extension-host service and is exposed to Copilot through VS Code's MCP server-definition provider and a loopback Streamable HTTP endpoint. Confirmed dispatch for terminal/debug versus Access and the distinction between bridge aliases and MCP tool IDs. No runtime tools or VS Code window state were changed.
