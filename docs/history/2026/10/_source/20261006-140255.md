## Working Hypothesis
The initial multi-device hypothesis was wrong. The diagnostic worker discarded native route IDs and synthesized `GPU`, even though OpenVINO enumerates `GPU.1` as the B70 and `GPU.0` as the UHD iGPU; successful historical runs used explicit `GPU.1`. Diagnostics now preserve the explicit Intel routes, order the B70 first, exclude NVIDIA, and the UI filters stale `GPU` profile/device settings. The rebuilt Studio shows `GPU.1` as the effective route.

The routing defect is fixed: the unchanged generic `GPU` setting resolves at runtime to `GPU.1`, and a fresh load log confirmed the B70 route. Short non-streaming and streaming OpenAI-compatible requests completed with `OK`; SSE included usage and `[DONE]`. A prior 32k-target attempt returned HTTP 200 but only the initial 279-byte SSE role chunk, then timed out at 600 seconds without usage, non-empty output, or `[DONE]`. Its actual prompt-token count and effective route remain unknown; that probe was not repeated. A later early client disconnect was followed by a successful status GET, but did not establish long-context support.

After the user's explicit request, one 128k-class probe was sent to the loaded `GPU.1` model. Its user message consisted of 131,000 repetitions of ` a`; the tokenizer JSON's BPE vocabulary contains `Ġa` as one token. The total model prompt count, including the chat template, was not returned. The server responded HTTP 200 and emitted only the initial assistant-role SSE chunk, with no usage, content, finish chunk, or `[DONE]`. The native stack reached `VLMPipeline.GenerateWithHistory` for this text-only request and threw `OVException` status `-17` (`UNKNOW_EXCEPTION`), whose wrapper message is only “Unknown error”. The kernel logged `xe 0000:03:00.0: [drm] VM worker error: -105` about four seconds after request start; Linux `-105` is `ENOBUFS`. This points to a GPU VM/buffer allocation failure during long-context inference, but does not distinguish capacity, fragmentation, or backend compatibility. After stopping Studio, host available RAM was 23 GiB, swap use about 3.8 GiB, port 7010 was free, and no kernel OOM/segfault was logged. The debugger adapter returned `ConnectionLostException` for continue and step-out, so the Studio session was stopped through EsiMCP; no second inference was started. The model advertises 262144 context, but the current 128k-class request did not pass. OpenVINO GenAI's `MAX_PROMPT_LEN` property is NPU-specific and must not be applied to this GPU route.
