### Debugger exception and root cause

The active Studio debug session is `b8669bf8-87a1-4b48-ab7b-1fd8ba04aa6b`; EsiMCP reported the host ready. The attached exception identifies the actual CUDA12 load failure: `LlamaCuda12Runtime.ConfigureNativeBackend` calls `NativeLibraryConfig.All.WithSearchDirectory` after an LLamaSharp native library was already loaded. LLamaSharp native configuration is process-wide and immutable after the first native API call. The earlier SYCL probe loaded it first; unloading SYCL weights does not unload or reset LLamaSharp's process-wide native library. `LlamaModelLoader` already has an explicit process-wide backend guard that says the process must restart before selecting another backend, but the packaged CUDA12 runtime uses its own `nativeConfigured` flag and reaches LLamaSharp's lower-level exception instead.

This confirms the CUDA12 failure is a backend-switch/process-lifetime constraint, not a timeout or CUDA device readiness issue. Do not retry in this Studio process. The benchmark procedure requires stopping the remaining sequence after this error. A fresh-process run would be a new sequence, but it was not started in this continuation.
