#### Findings and Validation

Its registry subprocess started a fresh Python interpreter and failed with `Only one platform plugin can be activated, but got: ['xpu', 'cuda']`; the in-process bootstrap monkey-patch was not inherited.
- A platform-discovery probe failed without `PYTHONPATH` and selected `vllm.platforms.xpu.XPUPlatform` when the bridge `Python` directory was placed in `PYTHONPATH`. `VllmXpuRuntime.ApplyDeviceEnvironment` now prepends that directory and retains any existing path entries.

A native oneCCL crash then occurred in `ccl::topo_manager::detect_tune_port_count`; diagnostics reported two Level Zero drivers but only one Sysman driver, leaving the selected root device without a Sysman handle.
- The runtime no longer sets or inherits `ZE_AFFINITY_MASK`, consistent with the earlier successful vLLM XPU session. A minimal XCCL all-reduce still segfaulted with the mask absent; setting `ZES_ENABLE_SYSMAN=1` did not change the driver-count mismatch. No further model-load attempts were made.
