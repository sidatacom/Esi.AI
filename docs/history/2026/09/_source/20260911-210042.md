## Findings
- LocalAI builds SYCL with icx/icpx, `-fsycl`, and `GGML_SYCL_F16=ON`.
- LocalAI packages `libze_intel_gpu`, `libigc`, and `libigdgmm` in addition to Level Zero/SYCL libraries.
- LocalAI `run.sh` sets `ZE_ENABLE_ALT_DRIVERS` to the bundled Intel Level Zero driver when its bundled loader is present.
- Esi.AI currently requires/copies `libur_adapter_level_zero.so` but no bundled Intel graphics driver is configured in the inspected code.
- The host driver files are versioned (`libze_intel_gpu.so.1.14.37020`, `libigc.so.2.28.4+0`, `libigdgmm.so.12.9.0`), so packaging must preserve glob matches and symlinks.
- Focused tests passed: installer tests 7/7, combined prerequisite/loader/installer tests 20/20; the packaging script passes `bash -n`.
- Unified Runtime 0.12's loader expects `libur_adapter_level_zero_v2.so.0`; the old adapter alone produced zero UR adapters even though direct Level Zero saw one GPU.
- The flat Esi runtime needs `UR_ADAPTERS_FORCE_LOAD` because the loader's `$ORIGIN/../lib` search path does not point at the flat runtime directory.
- Direct host probe found `Intel(R) Graphics [0xe223]`; Studio end-to-end SYCL load returned `foundGpuCount: 1`, device `SYCL0`, and loaded the 15.3 GB Qwen GGUF successfully.
- A persisted SYCL configuration still contains the generic `GPU1` alias and returns a validation error; the working native route uses `SYCL0`.

## Final changes
- Package the versioned Intel Level Zero driver, compiler, graphics-memory libraries, both Unified Runtime adapters, and exclude core libc-family dependencies from the transitive sweep.
- Configure `ZE_ENABLE_ALT_DRIVERS`, `ZES_ENABLE_SYSMAN`, and `UR_ADAPTERS_FORCE_LOAD` for the bundled SYCL runtime.
- Require the v2 adapter in installer prerequisites, development package configuration, and regression fixtures.
