# Session Log

## User Request

After any backend inference error, unload all model resources immediately and terminate the Esi.AI Studio process. Apply this behavior to every backend without adding tool/schema workarounds.

## Action Plan

- [completed] Read the shared inference dispatchers and runtime shutdown path.
- [completed] Add an idempotent fatal inference failure coordinator.
- [completed] Route SignalR and OpenAI-compatible generation failures through the coordinator.
- [completed] Add focused lifecycle tests.
- [completed] Run the Studio test project and correct the prior history finding.

## Findings

- `InferenceService` is the shared SignalR generation boundary.
- `OpenAiCompatibleBackendMiddleware` is the shared HTTP generation boundary for streaming and non-streaming requests.
- `ModelRuntime.StopAsync` is the existing backend-independent cleanup primitive.
- The native OpenVINO root cause remains unresolved; post-error requests cannot provide clean subset evidence because the runtime is poisoned.

## Implementation

- Added `IInferenceFailureCoordinator` and `InferenceFailureCoordinator`.
- The coordinator runs once, calls runtime cleanup with `CancellationToken.None`, logs cleanup failures, and requests `IHostApplicationLifetime.StopApplication()`.
- `ModelRuntime.StopAsync` now attempts LLama, OpenVINO, Python, and dotLLM independently, publishes the cleared model status, and is idempotent during host shutdown.
- Request validation and caller cancellation remain outside the fatal path.

## Verification

- Focused lifecycle tests passed: 2/2.
- Full Studio test project passed: 73 passed, 1 skipped, 0 failed.

## Summary

The application now treats backend generation failures as fatal process-lifecycle events across all local backends, while preserving ordinary request validation and user cancellation behavior.
