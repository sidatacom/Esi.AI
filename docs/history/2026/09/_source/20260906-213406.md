# EsiMCP Restart-ID und Rebuild-Task

## Anfrage

Den virtuellen EsiMCP-Restart so implementieren, dass VS Code niemals dieselbe Debug-Session-ID wiederverwendet; optional soll zwischen Stop und Start ein benannter `tasks.json`-Task ausgeführt werden. Danach testen, versionieren, paketieren und installieren.

## Änderungen

- `DebugManager.restartDebugging` verwendet Stop, optionalen exakten Task und expliziten Start.
- Recycelte Debug-Session-IDs werden abgelehnt; nur eine neue ID schließt den Restart erfolgreich ab.
- Der Task-Waiter behandelt auch sehr schnell endende Tasks ohne Race-Condition.
- `debug.restart` und `csdevkit.debug.restart` akzeptieren optional `rebuildTaskName`.
- README und Changelog wurden aktualisiert.
- Extension-Version auf `1.0.29` erhöht und alle Versionsträger synchronisiert.

## Validierung

- `npm test`: 10 Testdateien, 93 Tests bestanden.
- `npm run package`: Versionscheck, Build und VSIX-Erstellung bestanden.
- VSIX installiert: `sidatacom.vscode-esi-mcp@1.0.29`.
- TypeScript-Fehlerprüfung: keine Fehler.
- `git diff --check`: ohne Befund.

## Offen

- Ein neuer Extension-Host beziehungsweise ein Reload ist erforderlich, bevor ein bereits laufendes Extension-Host den neuen Bundle-Code verwendet.
- Der Live-Restart-Test mit einer tatsächlich neuen Session-ID und einem konkreten Rebuild-Task wurde nach der Installation noch nicht ausgeführt.
