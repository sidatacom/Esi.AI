# Sitzungsprotokoll

## Anfrage
`dotnet watch` meldet, dass die Fluent-UI-Projekte unter `origins/sidatacom/fluentui-blazor` mit der Erweiterung `.esproj` keiner Sprache zugeordnet sind. Das Problem soll behoben werden.

## Aktionsplan
- [x] Ermitteln, wodurch `dotnet watch` die beiden `origins`-Projekte einliest.
- [x] Lokale Projekt-/Solution-Konfiguration und relevante Arbeitsanweisungen prüfen.
- [x] Die kleinste passende Konfigurationsänderung umsetzen, ohne `origins/` als Esi.AI-Quellcode zu behandeln.
- [x] Den betroffenen Watch-/Build-Pfad gezielt validieren.
- [x] Ergebnis und verbleibende Einschränkungen zusammenfassen.

## Ausführung

- `dotnet watch` überwacht standardmäßig den transitiven `ProjectReference`-Graphen.
- `Watch="false"` wurde auf allen direkten Projektverweisen in `Esi.AI.Studio.csproj` gesetzt.
- Die Fluent-UI-Verweise in `Esi.AI.Studio.Client.csproj` bleiben ebenfalls aus dem Watch-Graphen ausgeschlossen.
- `dotnet watch --list --no-restore` erfolgreich: keine Dateien aus Client, Core, Models, Contracts, `origins/` oder `.esproj`.
- `dotnet build .../Esi.AI.Studio.csproj --no-restore` erfolgreich: Build der vollständigen Referenzkette bleibt aktiv.

## Zusammenfassung

Der Hot-Reload-Watch-Graph ist auf `Esi.AI.Studio` begrenzt, ohne die normalen Projektverweise aus dem Build zu entfernen. Änderungen in abhängigen Projekten lösen dadurch keinen Watch-Neustart mehr aus.
