# Sitzungsprotokoll

## Benutzeranfrage
Der Readiness-Bool der virtuellen Debug-Session-Kommandos soll pro aktiver VS-Code-Debug-Session-ID gespeichert werden.

## Arbeitsstand
- DAP-Output wird bereits sessionbezogen empfangen.
- `SessionManager` verwendet für Readiness noch globale Zustände.
- Die Umstellung soll Map-basierte Zustände, sessionbezogenes Zurücksetzen und Live-Auslesen der aktiven Session-ID umfassen.

## Aktionsplan
- [ ] Readiness-Zustand in `SessionManager` pro Session-ID modellieren.
- [ ] DAP-Output und Terminierung auf die jeweilige Session-ID begrenzen.
