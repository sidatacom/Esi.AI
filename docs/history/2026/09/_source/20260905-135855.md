# Sitzungsprotokoll

## Benutzeranfrage

Der Benutzer weist darauf hin, dass die laufende Studio-Debugsession wegen einer UI-Änderung unnötig gestoppt wurde und bittet darum, die Regeln so zu ändern, dass künftig Hot Reload bevorzugt wird.

## Aktionsplan

- [x] Bestehende Studio-Build-/Debug-Regeln prüfen und den Hot-Reload-Fall abgrenzen.
- [x] Die projektweiten Copilot-Regeln um eine Hot-Reload-Priorität für geeignete UI-Änderungen ergänzen.
- [x] Die geänderte Regel auf Konsistenz und Markdown-Format prüfen.
- [x] Den Abschluss und die neue Entscheidungslogik dokumentieren.

## Ergebnis

- Die projektweiten Regeln priorisieren jetzt Hot Reload für laufende Studio-Debugsessions bei geeigneten Razor-, CSS-, Markup- und Client-Änderungen.
- Eine Session darf für Browserprüfung oder einen unnötigen separaten Build nicht mehr gestoppt werden.
- Stop oder Debug-Restart bleibt für nicht hot-reload-fähige Änderungen, notwendige vollständige Builds und Server-/Projektänderungen vorgesehen.
- `git diff --check` für die geänderten Regel- und Logdateien war erfolgreich.
