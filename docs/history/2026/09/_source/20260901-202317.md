## Summary

The repository rules were present but advisory only. The VS Code launch configuration starts the watchdog as a sibling task and launched the Studio process without a startup trust check. Studio now requires `ESI_AI_STUDIO_WATCHDOG_PID_FILE`, verifies the PID file names a live process whose command line contains `studio-watchdog.sh`, and refuses startup otherwise. The supervised launch supplies the marker; direct `dotnet run` and binary launches do not. Start and stop tasks use the same explicit marker even when `TMPDIR` differs, and stop validates the PID before sending a signal. The Studio build passed, the shell and JSON checks passed, no diagnostics were reported for `Program.cs`, and no Studio/watchdog process or listener remained on port 7010.
