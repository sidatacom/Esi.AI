# Session Request

User asks what the VS Code Copilot Chat documentation and the OpenAI-compatible API documentation imply about the SSE heartbeat implementation.

## Action Plan

- [complete] Review the VS Code Language Model Chat Provider streaming contract.
- [complete] Review OpenAI-compatible Chat Completions streaming and SSE keep-alive guidance.
- [complete] Compare those contracts with the current Studio heartbeat behavior.
- [complete] Provide a concise recommendation without changing code.

## Findings

- VS Code's LanguageModelChatProvider contract requires response parts through the progress callback and supports cancellation; it defines no heartbeat event.
- OpenAI Chat Completions streaming is a sequence of SSE chat completion chunks, followed by `data: [DONE]`; the reference does not require heartbeat frames.
- WHATWG SSE explicitly permits colon-prefixed comment lines and recommends sending them about every 15 seconds to protect long-lived connections from legacy proxies.
- The Studio heartbeat is therefore valid transport-level hardening and should be ignored by the provider parser. It can help only when an intermediary drops an otherwise healthy idle connection.
- It cannot repair a hung native generation, stale Studio process, cancellation, or a server-side connection failure. Those remain the primary investigation targets.

## Summary

Documentation supports retaining the heartbeat as an optional keep-alive, while treating it as unrelated to the OpenAI semantic contract and VS Code tool-call contract. A real long-running Agent request should be used to prove whether an intermediary idle timeout exists before calling the heartbeat a fix.
