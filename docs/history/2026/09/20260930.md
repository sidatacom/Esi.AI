# Session Log

## User Request
Determine whether device-routing selections are cleanly persisted and reloaded in each backend's configuration.

## Action Plan
- [x] Trace device selection controls to state mutation and save operations in the client.
- [x] Trace each backend's serialized configuration through persistence and reload, including any exceptions between backend families.
- [x] Answer with concrete guarantees and caveats, without changing code unless a defect is found that needs immediate correction.
- [x] Record findings and the final response in this log.

## Findings
- LLama device selection is serialized as `DeviceWeights`/selected devices in `LoadModelRequest`, written to `ModelSettings`, and restored during page initialization.
- OpenVINO device selections are serialized in `OpenVinoState.ToSettings()`, written to `ModelSettings`, and restored through `OpenVinoState.Load()`.
- vLLM and SGLang selections are `PythonState.Devices` plus the legacy primary `Device`; `ToRequest()` serializes both. With a selected per-model profile and non-empty model path, `SaveSettingsAsync()` updates that profile's `ConfigurationJson`, and `TryApplyProfile()` restores it.
- vLLM/SGLang and dotLLM have no `ModelSettings` fallback in `SaveSettingsAsync()`. If no profile is selected, `PersistCurrentProfileSettingsAsync()` returns without writing; selection then exists only in page memory and is lost on reload. This is a persistence gap, not a complete guarantee.
- `ModelConfiguration.BackendVariantId` keeps vLLM CUDA and XPU profiles distinct, and profile lookup filters by runtime variant.
- No source code was changed for this inspection.

# Session: Strata-Integration bewerten

## Nutzeranfrage
Der Nutzer fragt, ob Esi.AI Strata integrieren kann und ob Strata eine spezielle llama-Version ist. Kontext: Video beschreibt Strata als Laufzeit für Qwen3.8-Flash-Next mit MoE-Offloading (GPU/RAM/SSD) und MTP; es nennt Leistungsangaben, Parameterzahl und Lizenzbedenken.

## Arbeitsplan
- [x] Strata-Repository, Lizenz, Modellunterstützung und Laufzeitmodell anhand der aktuellen Projektquellen verifizieren.
- [x] Esi.AI-Modellruntime und vorhandene Integrationsgrenzen lokal prüfen.
- [x] Integrationspfad, Abgrenzung zu LLamaSharp/llama.cpp und relevante Einschränkungen knapp beantworten.

## Ergebnis
Strata ist eine eigenständige C++/CUDA-Inferenz-Engine, die Teile von llama.cpp/ggml nutzt, aber kein spezieller llama-Modelltyp und kein LLamaSharp-Backend ist. Der aktuelle Strata-Server exponiert eine OpenAI-kompatible API. Esi.AI besitzt Runtime-Module/Resolver für austauschbare Backends, aber der eingebaute Python-Bridgepfad ist konkret auf vLLM und SGLang beschränkt. Eine lokale Integration ist daher grundsätzlich machbar, benötigt aber ein eigenes Backend-Modul/Runtime samt Modellstatus-, Lifecycle- und Chatstream-Anbindung; ein äußerer API-Proxy wäre ein kleinerer separater Weg, sofern Esi.AI eine entsprechende Client-Provider-Anbindung ergänzt.

Das aktuelle Strata-GitHub-Repository zeigt eine MIT-Lizenz. Modelldateien behalten ihre jeweiligen Modelllizenzen. Qwen-Modellkarte weist 125B Basisparameter plus 51B N-Gram-Einbettungen aus; die HF-Dateiübersicht zeigt rund 180B gespeicherte Parameter, was den scheinbaren Widerspruch plausibel erklärt. Im Video behauptete Detailwerte wurden nicht einzeln reproduziert/verifiziert.

Quellen: https://github.com/Niko1221/Strata, https://huggingface.co/Qwen/Qwen3.8-Flash-Next, https://unsloth.ai/docs/models/qwen3.8-next; lokale Esi.AI-Laufzeit: `src/Esi.AI/Esi.AI.Core/ModelLoading/ModelRuntime.cs`, `PythonInferenceServer.cs`, `BackendRuntimeAdapters.cs`.

## Folgeaktion
Strata auf Wunsch des Nutzers als Git-Submodul unter `origins/Niko1221/Strata` hinzugefügt. Remote: `https://github.com/Niko1221/Strata.git`, Branch `main`, geprüfter Stand `a79080535d1b2a71a3419a0d97d8e7dca194b0f1` (v0.1.27). Verifiziert mit `git submodule status` und Remote-Abfrage. Vorbestehende Änderungen im Arbeitsbaum blieben unberührt.

- [x] Inspect initialization flows and relevant service implementations/contracts.

- [x] Document recommendations, caveats, and verification limits.

## Findings
Scope: eight client routes use `InteractiveAuto`. `Auth` and `NotFound` do not. `WebApi` has no page-level SignalR/data-service initial read. Of the named `*PageState` wrappers, only `BackendPageState` and `ChatPageState` are actually dereferenced by their pages; `HomePageState`, `ModelsPageState`, `ProviderPageState`, `SettingsPageState`, and `WebApiPageState` are not the backing containers for the data read during initialization.

| Route | Initial data reads | `PersistentState` assessment |
| --- | --- | --- |
| `/backends` | Loaded-model status; application/model settings; local model scan and database model sync; configurations; selected backend models; selected backend diagnostics/device discovery; OpenVINO status; backend requirements. | Strong fit for small, stable selection/configuration snapshots. The enabled backend IDs are already transferred. Persisting just those IDs does not skip the later `ApplicationSettings_ReadAsync`; a complete safe bootstrap DTO would need the other settings used to choose the active backend. Avoid transferring the entire form/state tree. Device discovery and diagnostic results are host/runtime observations; prefer a fresh read or treat any transferred value as a short-lived snapshot. `Model_UpdateAsync` and `BackendModel_ReadAsync` both reach `LocalModel_ReadAsync`, so local catalog scans are duplicated even before considering prerender versus WASM. |
| `/chats` | Loaded models; local model catalog; unbounded chat-summary list; first selected chat including all messages. | Loaded-model status is a compact-snapshot candidate. Local models have the same scan/size tradeoff as `/models`. Do not transfer all chats or the full selected transcript by default: count and message bodies are unbounded, chat titles may contain user text, and contents can be sensitive. A bounded summary page could be considered after adding pagination/limits. Composer/image state is transient UI state, not an initial read; an image preview may be large. |
| `/flow` | Full flow-definition list, then the selected definition JSON or a generated default. | Optional candidate if definitions are bounded and contain no secrets. The page already renders a loading placeholder, so this is a performance optimization rather than a correctness fix. Do not persist the entire list blindly because definition JSON is user-editable and has no observed size bound. |
| `/home` | `LoadedModel_Read` into the active-model store. | Good candidate for a compact initial runtime snapshot; it avoids an empty/stale first render and is small in normal cases. The returned contract includes `LoadLog`, paths, and device details, so prefer a display/bootstrap projection or size limit. SignalR updates remain authoritative after hydration. |
| `/models` | Loaded-model status (also used for detected hardware); local model scan; model directories. Search results are fetched only after user search. | Model directories are a good small snapshot. The local catalog scan may include many models and model paths, and performs metadata/database work; transfer only if measured scan cost outweighs HTML payload size, or add paging. Loaded-model status is a compact candidate, preferably without logs. Search results are not initial data and should not be persisted on page load. |
| `/provider` | Loaded-model status and provider trace entries. The trace store is capped at 200 entries, but each entry has an optional arbitrary payload. | Loaded-model status is a compact candidate. Do not persist raw trace payloads wholesale: they can contain prompts/request details and grow substantially. A redacted, size-bounded trace summary could be transferred if initial trace rendering is important. |
| `/settings` | Application settings; backend runtime package options; flow definitions. | Runtime options and ordinary timeout/configuration fields are reasonable bounded candidates. Do not persist `ApplicationSettings` as-is: `ModelLibrarySettings` includes the Hugging Face token. Use a redacted bootstrap DTO that excludes the token and populate secret-presence state separately. Flow definitions have the same size/content caveat as `/flow`. |
| `/webapi` | No `IDataService` or SignalR initial read; embeds Swagger in an iframe. | Nothing to persist for page data. |

## Cross-Cutting Recommendation
- `[PersistentState]` is a one-time prerender-to-interactive handoff, not a cache across client-side route navigation. Keep SignalR reads as the fallback for client-only navigation and SignalR events as the post-hydration update path.
- The attribute alone does not skip an initial read. The page must detect a restored snapshot and avoid repeating only the corresponding read; the current backend-tab fix applies transferred IDs early but still reads `ApplicationSettings` for other initialization fields.
- Persist focused, bounded DTO snapshots rather than entire `*PageState` objects. Exclude secrets, user-authored/private text, image payloads, large logs, and volatile diagnostics unless explicitly projected/redacted and size-limited.
- No application code was changed during this audit. Findings are based on source paths and contracts; payload sizes were not measured in a populated large-model/chat installation.
