# Request

Fix Llama CUDA 12 device discovery so the NVIDIA GeForce RTX 4070 is shown, while preserving the working Llama SYCL 16 behavior that shows the Intel GPU.

# Action Plan

- [x] Inspect CUDA native backend selection and verify whether `CUDA_VERSION=12` enables bundled CUDA loading.
- [x] Inspect CUDA shared-library dependencies and check for system CUDA runtime libraries.
- [x] Check local CUDA runtime locations; verify discovery succeeds when CUDA 12 libraries are on the worker loader path.
- [x] Pass CUDA 12 selection and available CUDA runtime paths through the constrained systemd worker launch without changing SYCL.
- [x] Build Studio and verify the direct systemd worker probe returns the RTX 4070.
- [x] Trace why the Studio browser route still displayed zero CUDA devices; remove the diagnostic breakpoint that paused the worker.
- [x] Diagnose the follow-up EF `TaskCanceledException` as request-token cancellation behavior; do not suppress cancellation without evidence of a live-request failure.

# Findings

- LLamaSharp `NativeLibraryWithCuda` uses the CUDA toolkit major version to select CUDA 12; setting `CUDA_VERSION=12` alone did not produce devices.
- `ldd` reports `libcudart.so.12` and `libcublas.so.12` missing from the deployed CUDA runtime directory and the system linker cache.
- `nvidia-smi` detects the NVIDIA GeForce RTX 4070; Vulkan also enumerates it. The CUDA worker response remains empty.
- CUDA 12 runtime libraries are available under the user's LM Studio vendor directory. A worker launched through a systemd scope with explicit `--setenv` returns `CUDA0` for the NVIDIA GeForce RTX 4070.
- The Studio build succeeds. The first UI retest was blocked by a retained diagnostic breakpoint. After removing it, Studio displays exactly one CUDA device: `NVIDIA GeForce RTX 4070` (`CUDA0`).
- The SYCL 16 UI regression check displays exactly one Intel device: `Intel(R) Graphics [0xe223]` (`SYCL0`).
- The debugger also exposed and fixed optional environment-variable indexers that threw `KeyNotFoundException` before the CUDA worker could start.
- `OpenAiCompatibleController.ListModels` passes the HTTP request cancellation token into `DataService.LocalModel_ReadAsync`, where EF Core uses it in `ToDictionaryAsync`. A canceled request can produce this `TaskCanceledException`; the original token state was not available in the paused frame, but an uninterrupted request succeeds.
- A direct, uninterrupted `GET /v1/models` returned HTTP 200 with the configured model list. This confirms the current non-canceled EF query path completes successfully.

# Summary

Completed: the constrained CUDA worker receives `CUDA_VERSION=12` and the discovered runtime-library path through `systemd-run --setenv`; Studio shows only the NVIDIA RTX 4070 for Llama CUDA 12 and only Intel for Llama SYCL 16. An uninterrupted `/v1/models` request returns HTTP 200. The reported EF `TaskCanceledException` is consistent with cancellation propagated from the HTTP request into EF Core, particularly during debug/browser reloads; no database failure was reproduced and no cancellation should be swallowed. The Studio session is left running at `http://localhost:7010/backends` for interactive use.
