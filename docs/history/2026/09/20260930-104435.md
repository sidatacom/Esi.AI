## Summary
- Root cause: the server prerender reads `ApplicationSettings` through `DataService`, but InteractiveAuto creates a separate WebAssembly instance using `SignalRDataService`. The client instance started with `enabledBackendTabs` initialized to every enum value, and only applied saved `EnabledBackendIds` after an asynchronous SignalR read. No state was transferred across prerender and hydration.
- Fix: persist the prerendered enabled backend IDs with Blazor `[PersistentState]`, apply them synchronously in `OnInitialized`, and keep the tab navigation hidden until visibility has loaded when no prerender state exists.
- Validation: `Esi.AI.Studio.Client` build succeeded. A full browser reload kept the backend-tab count at six throughout sampling; server-rendered HTML with Blazor JavaScript blocked also contained the same six tabs. Studio host readiness was confirmed.
- `git diff --check` passed for the changed backend page with `core.whitespace=cr-at-eol`.
- No automated component test was added; the reload/hydration behavior was checked in the running Studio browser.
