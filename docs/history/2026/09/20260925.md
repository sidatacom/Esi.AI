## 20260925-183247.md

# User Request
Research online and in source code how to disable user prompts for all C# Dev Kit commands.

# Action Plan
- [done] Inspect installed C# Dev Kit command registrations and contributed settings for global or prompt-specific controls.
- [done] Trace available prompt behavior without reverse-engineering the closed-source extension bundle.
- [done] Inspect EsiMCP command forwarding to distinguish wrapper capabilities from C# Dev Kit capabilities.
- [done] Research official VS Code command API and C# Dev Kit documentation for supported prompt-suppression options.
- [done] Report whether global suppression is supported, what narrower workarounds exist, and any limitations.

# Findings
- C# Dev Kit is closed source. Its installed manifest points to Microsoft's internal `vs-green` repository, and its license prohibits reverse engineering. The separate C# extension is open source; `microsoft/vscode-dotnettools` is a feedback repository.
- The C# Dev Kit 3.40.210 manifest has no global prompt/confirmation setting. Narrow settings include `dotnet.debug.suppressInvalidDebugTypeWarning`, `dotnet.suppressSdkInstallView`, and test-runner settings that disable builds on test refresh/run.
- VS Code `commands.executeCommand` accepts command-specific arguments; it has no universal prompt-suppression parameter. The message API exposes message options such as `modal` and `detail`, not a global suppression option.
- Public issue microsoft/vscode-dotnettools#1891 reports the failed-build/last-successful-build prompt. The reporter says `debug.onTaskErrors: "abort"` did not suppress it; the issue is open and points to an internal `DotnetDebugConfigurationService.ts` source path.
- EsiMCP forwards ordinary C# Dev Kit commands directly. Its `executeHotReloadSilently` wrapper temporarily overrides `showErrorMessage`, `showWarningMessage`, and `showInformationMessage` only for Hot Reload. This cannot suppress every UI interaction and is not a supported Dev Kit API.
- For the failed-build prompt, the reliable non-invasive mitigation is to preflight the build and skip launch on failure; do not ask the launcher to run the last successful binary. No universal suppression mechanism was found.

# Summary
No supported global switch/API exists to disable user prompts for all C# Dev Kit commands. Prompt suppression is command-specific where a setting exists; API monkey-patching is partial and risky. The Dev Kit's implementation source is not publicly available, so conclusions about its internal prompt handler are limited to official documentation, package metadata, and the public issue tracker.
