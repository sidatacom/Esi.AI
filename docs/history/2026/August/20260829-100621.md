# Session Log

## User Request
Assess how to isolate LLama and OpenVINO from the Studio process, sandbox and monitor them, and terminate a backend process when it consumes too much CPU or freezes after the machine froze twice.

## Action Plan

- [x] Recommend a staged architecture that preserves the existing SignalR and DTO boundaries.
- [x] Identify the minimum refactoring required before implementation.
- [x] Summarize risks, especially native GPU driver hangs and machine-level freezes.

## Findings
- `ModelRuntime` currently owns native LLamaSharp and OpenVINO loaders inside the Studio process.
- `DataService` creates native chat sessions directly through `ModelRuntime`; OpenVINO generation is synchronous and has no cancellation token.
- A cancellation token can stop cooperative managed work but cannot reliably interrupt a native call that is blocked in a GPU driver.
- Reliable killability requires model loading and inference to run in a child worker process controlled by Studio.

## Recommendation
Use one killable worker process per backend: `LlamaWorker` and `OpenVinoWorker`. Keep `DataHub` and the shared DTO contracts unchanged, but replace live chat-session returns with request/response generation methods. Communicate over a local Unix domain socket using a small versioned JSON-RPC protocol. Run each worker under a dedicated cgroup/systemd user unit with `CPUQuota`, `MemoryHigh`, `MemoryMax`, `MemorySwapMax`, and `TasksMax`. The parent owns startup, request deadlines, heartbeat/health state, process-group termination, restart backoff, and circuit breaking.

Short-term mitigation while the workers are being built: cap LLama threads, context size, and GPU layers; keep OpenVINO on a single explicit device instead of `MULTI`; serialize load/unload; reject loads after a memory preflight; and add operation timeouts. These reduce risk but cannot terminate an in-process native hang.

Alternatives considered: in-process cancellation/timeouts are insufficient for native blocking calls; AppDomains do not isolate native code in modern .NET; containers add deployment and Intel GPU passthrough complexity but are suitable for production; a hardware/kernel GPU deadlock can still freeze the machine and requires driver/kernel remediation or host-level recovery.

## Host Watchdog
Use an external `systemd` supervisor for `Esi.AI.Studio` as a second safety layer. It should restart Studio after an unexpected exit and optionally enforce Studio-level cgroup limits. A systemd watchdog heartbeat must be emitted by the process or an external health checker; merely setting `WatchdogSec` is not sufficient. The worker watchdog remains responsible for terminating native inference workers on operation timeout. Killing Studio is a recovery path, not the primary response to a backend hang, because it also drops the UI and SignalR connections.

## Debug Session
Added `.vscode/studio-watchdog.sh` and wired it into `.vscode/launch.json` and `.vscode/tasks.json`. F5 now builds Studio, starts the watchdog as a background task, launches the normal CoreCLR debug process on port `7010`, and stops the watchdog through `postDebugTask`. The watchdog performs a local HTTP health check every three seconds, terminates Studio after ten consecutive failures, and supports an optional `STUDIO_WATCHDOG_MEMORY_LIMIT_MB` RSS limit. CPU thresholds are intentionally not enabled by default because model loading can legitimately saturate CPUs; a hard CPU cap belongs in a systemd/cgroup launch configuration.

## CSS Diagnosis and Fix
The unstyled `/backends` page was caused by the client CSS-isolation bundle not being linked from `Components/App.razor`. The stable asset key is `Esi.AI.Studio.Client.bundle.scp.css`, which resolves to the fingerprinted bundle at runtime. An incremental build had also retained an empty generated `Backends.razor.rz.scp.css`; removing only the generated `obj/Debug/net10.0/scopedcss` directory and rebuilding regenerated the page rules.

The manual verification initially failed because Studio was started from the workspace root, so `appsettings.Development.json` was not found. Starting from `src/Esi.AI/Esi.AI.Studio`, matching the F5 `cwd`, loaded the Development configuration and served the rebuilt assets. Browser verification confirmed the client bundle is active, `backend-tab` styles are applied, and the page layout is restored. The watchdog configuration was not the cause; it only monitors the already-started process.
