## Ausfuehrung

- Der Fehler lag in `Backends.razor`: `InitializeAsync()` rief `GetModelStatusAsync()` fuer LLama auf, aber nicht `GetOpenVinoModelStatusAsync()`.
- Der Fix setzt `isOpenVinoModelLoaded` aus dem serverseitigen Status und uebernimmt bei geladenem Modell Pfad und Device.
- Der Studio-Build war erfolgreich.
- Frischer Host auf `http://127.0.0.1:5212` gestartet.
- OpenVINO Qwen3.8 auf `GPU.1` geladen.
- Navigation `Backends -> Chats -> Backends` erfolgreich: Chat zeigte `Qwen3 (OpenVINO)`; Backends zeigte `MODEL LOADED`, `Qwen3.8-27B-int4-ov | GPU.1` und eine Modellkarte.
- Der sichtbare Host auf `http://localhost:7010` verwendet noch nicht sicher den neuen Build und muss nach dem Build neu gestartet werden.
- Core-Tests: 18 gesamt, 16 erfolgreich, 0 fehlgeschlagen, 2 uebersprungen.
- Gesamte Loesung: erfolgreich gebaut; `Backends.razor` meldet keine Fehler.
- Der isolierte Host auf `http://127.0.0.1:5212` wurde nach der Validierung beendet.

## Offene Punkte

Keine offenen technischen Punkte.

## Zusammenfassung

Die Ursache war ein fehlender OpenVINO-Statusabruf in `Backends.razor` beim erneuten Initialisieren der Seite. Der Status wird jetzt ueber den zentralen `IDataService` aktualisiert; bei einem geladenen Modell werden auch Modellpfad und Device uebernommen. Der Ablauf Laden -> Chats -> Backends wurde mit Qwen3.8 auf GPU.1 erfolgreich bestaetigt: `MODEL LOADED`, Modellkarte und Device bleiben sichtbar.
