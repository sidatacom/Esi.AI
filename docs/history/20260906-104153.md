## User request

The model-loading event system does not update the UI. When the user clicks `Load model`, loading logic must be activated through a handler. Show the relevant code so the user can identify when and where an event should be emitted to display the model under `Active runtimes`.

## Tracking

## Findings

- The button in `Backends.razor` calls `LoadActiveBackendModelAsync`, which dispatches to the backend-specific load handler.
- `ModelRuntime.TrackPendingModelAsync` publishes `LoadedModel_Create` before the backend load, `LoadedModel_Update` after completion, and `LoadedModel_Delete` on failure.
- `SignalRDataService` receives those SignalR messages, updates `ClientStateStore`, and invokes the page handler.
- `Backends.razor` assigns the received snapshot to `loadStatus` and calls `StateHasChanged`.
- OpenVINO also routes through `ModelRuntime.LoadAsync(OpenVinoLoadRequest)`, so it uses the same lifecycle publisher.
- No source code changes were made; the relevant event timing was shown to the user for confirmation.
