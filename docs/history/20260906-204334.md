## Ergebnis

- Das Debug-Console-Log zeigte für die aktive Session korrekte DAP-Output-Events, aber keinen Readiness-Latch; der Readiness-String war deshalb vermutlich auf mehrere DAP-Output-Chunks verteilt.
- EsiMCP puffert nun DAP-Output je Session und sucht im zusammenhängenden Puffer nach dem Readiness-String. Der Latch wird weiterhin entlang der Parent-Session-Kette gesetzt.
- Das Chunk-Logging wurde entfernt, weil es den Output-Channel unnötig stark füllte.
- EsiMCP auf `1.0.26` erhöht: `package.json`, `package-lock.json`, MCP-Server-Handshake, `server.json` und Changelog sind synchron.
- `npm run version:check` erfolgreich; fokussierte Readiness-/Debug-/C#-Dev-Kit-Tests erfolgreich: 29/29.
- `vscode-esi-mcp-1.0.26.vsix` gebaut und mit `code --install-extension --force` installiert; VS Code meldet `sidatacom.vscode-esi-mcp@1.0.26`.
- Der Extension Host muss vor einem erneuten Live-Lifecycle-Test neu geladen werden.
