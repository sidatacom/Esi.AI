## User request

Implement the Hugging Face download queue so that each selected model is one aggregate queue entry. Multiple aggregate entries may run in parallel, and all files or shards belonging to one entry may download in parallel. Show aggregate and per-file progress in the SignalR-driven Blazor UI. Keep downloads in the backend through the named Hugging Face HttpClient.

## Implementation summary

- Added configurable `MaxParallelDownloads` with a default of 3.
- The backend queue keeps one `DownloadOperation` per model selection and uses a semaphore to run multiple aggregate operations concurrently.
- Every selected file in an aggregate operation is started with `Task.WhenAll`.
- Shared `DownloadStatus` now carries `DownloadFileStatus` entries and per-file percentages.
- The Models page keeps one transfer row per aggregate operation and exposes nested shard progress in a details section.
- The integration test verifies two aggregate operations and four simultaneous shard requests.
