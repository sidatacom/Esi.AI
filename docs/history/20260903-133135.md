## Working hypothesis

The OpenVINO WebAPI chat failure is likely caused by a request-contract or runtime mapping regression rather than a compile-time problem. The discriminating check is a minimal chat request against the running OpenAI-compatible endpoint and its server response/log.

## Provider log findings

- The relevant tool-optimizer activity occurred on 2026-09-03 between 11:39:17Z and 11:39:48Z.
- Four parallel `POST /v1/chat/completions` requests were accepted with HTTP 200 and `text/event-stream` responses. Their requests used `max_tokens: 65536`, `stream: true`, and `tools: []`.
- Two streams emitted only the initial assistant role chunk. Two emitted text chunks and reached the provider's bounded trace message, but none of the four streams emitted `[DONE]`.
- The seven `[DONE]` markers in the file belong to the older 2026-09-02 run and do not validate the stuck interaction.
- After the four POSTs, the provider repeatedly queried `GET /v1/models` approximately every five seconds. The later log contains no further chat POST for the stuck interaction.
- `OpenVinoModelLoader` already serializes generation through `generationLock`. `OpenAiCompatibleController` does not emit `[DONE]` until native generation returns, so a long or non-terminating OpenVINO generation leaves the SSE request open.
- The provider's `requestTimeoutMs` timer is cleared as soon as `fetch` receives response headers; it does not time out an SSE body read. This is a separate provider robustness issue and was not changed in this diagnostic pass.

## Diagnostic conclusion

The log proves an incomplete SSE lifecycle for the tool-optimizer requests, not an HTTP connectivity failure. The strongest immediate suspect is the configured `max_tokens: 65536` combined with four parallel optimizer requests and serialized OpenVINO generation. No source code or packaged provider files were changed in this pass; a repair should first reproduce with a fresh log and a bounded optimizer request, then separately add stream-read cancellation handling if the backend completes without `[DONE]`.
